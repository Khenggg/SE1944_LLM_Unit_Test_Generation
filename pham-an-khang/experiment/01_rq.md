# Research Question — LLM for Unit Test Case Generation

**For Java/Python functions at medium cyclomatic complexity (P), could GPT-4 automatic generation of unit test cases (I) compared to manually written test cases (C) achieve >=74% branch coverage and >=58% mutation score (O)?**

---

## PICO Board

| Element | Description |
|---|---|
| **P – Population** | Java/Python functions at medium cyclomatic complexity (typically CC = 5–15) |
| **I – Intervention** | GPT-4 automatic generation of unit test cases |
| **C – Comparison** | Manually written test cases (developer-written / student-written) |
| **O – Outcome** | ≥74% branch coverage **and** ≥58% mutation score |

### Detailed Breakdown

#### Population (P)

- **Language**: Java and/or Python source code.
- **Granularity**: Function-level or method-level units (not class-level or project-level testing as a whole, unless data can be isolated at the method level).
- **Complexity**: Medium cyclomatic complexity (CC ≈ 5–15). This represents code with a moderate number of execution paths, decision points, loops, or conditional statements. Measured via tools such as Lizard (Python/Java), Radon (Python), or PMD/Metrics (Java).

#### Intervention (I)

- **Tool**: GPT-4 (including variants like GPT-4-Turbo, GPT-4o, or GPT-4o-mini).
- **Task**: Automatic generation of unit test cases directly from the source code under test.
- **Method**: Prompting techniques including zero-shot, few-shot, chain-of-thought, or structured template prompting.
- **Output**: Syntactically valid, compilable, and executable unit test suites (e.g., JUnit for Java, pytest/unittest for Python).

#### Comparison (C)

- **Baseline**: Manually written test cases authored by human developers (professionals, open-source contributors) or students.
- **Context**: Hand-crafted test suites representing standard developer effort (e.g., tests from project repositories, coding assignments, or benchmark baselines).
- **Secondary Comparison** (Optional): Performance against established automated test generation tools (e.g., EvoSuite, Randoop, CodaMosa) may be reported, but a human baseline is required.

#### Outcome (O)

- **Branch Coverage ≥ 74%**: The percentage of decision branches (e.g., if/else conditions, loops) executed by the generated test suite, measured using tools such as JaCoCo or Cobertura (Java) and coverage.py (Python).
- **Mutation Score ≥ 58%**: The percentage of seeded semantic faults (mutants) successfully killed by the test suite, measured using mutation testing engines such as PIT / PITest (Java) and MutPy / mutmut (Python).
- **Success Criterion**: The study must evaluate whether GPT-4-generated tests can achieve **both** thresholds simultaneously to answer the RQ in the affirmative.

> [!NOTE]
> **Threshold Adjustment Notice:**
>  The original initial threshold values were set at ≥80% branch coverage and ≥60% mutation score. However, as the experimental design evolved and the team reviewed the merged evidence table, these targets were formally adjusted to ≥74% branch coverage and ≥58% mutation score. This adjustment aligns the study with state-of-the-art empirical baselines—specifically the performance of GPT-4 on the rigorously controlled UnLeakedTestBench (ULT benchmark), providing a scientifically grounded and realistic floor value.
