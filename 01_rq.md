# Research Question

**For Java/Python functions at medium cyclomatic complexity (P), could GPT-4 automatic generation of unit test cases (I) compared to manually written test cases (C) achieve >=80% branch coverage and >=60% mutation score (O)?**

---

## PICO Board

| Element | Description | Supporting SLR Papers |
|---|---|---|
| **P – Population** | Java/Python functions at medium cyclomatic complexity (typically CC = 5–15) | `AX001`, `AX002`, `AX003`, `AX005`, `AX006`, `AX007`, `CORE001`, `AX009` |
| **I – Intervention** | GPT-4 automatic generation of unit test cases | `AX001`, `AX002`, `AX003`, `AX005`, `AX006` |
| **C – Comparison** | Manually written test cases (developer-written / student-written) | `AX003`, `AX005`, `AX006`, `AX007`, `CORE001`, `AX009` |
| **O – Outcome** | ≥80% branch coverage **and** ≥60% mutation score | `AX001`, `AX003`, `AX005`, `AX006`, `AX007`, `CORE001`, `AX009` |

---

## Detailed PICO Breakdown & Mapping to Our SLR Evidence

### 1. Population (P)
* **Language & Granularity**: Source code written in **Java** and/or **Python** at the function/method-level.
  * **Java**: Evaluated by 5 of our papers (`AX002`, `AX005`, `AX006`, `AX007`, `CORE001`).
  * **Python**: Evaluated by 6 of our papers (`AX001`, `AX002`, `AX003`, `AX007`, `CORE001`, `AX009`).
  * *Cross-language studies*: `AX002`, `AX007`, and `CORE001` evaluate both languages.
* **Complexity**: Medium cyclomatic complexity (CC ≈ 5–15), representing code with moderate branch branching, loops, and decision paths.
  * `AX005` systematically evaluates the impact of source code complexity on the unit test generation capability of LLMs.
  * `AX007` (HITS) applies method slicing to reduce complexity boundaries, allowing LLMs to achieve higher coverage on complex structures.

### 2. Intervention (I)
* **LLM Tool**: **GPT-4 series** (including GPT-4, GPT-4o, and GPT-4-Turbo).
  * `AX001`, `AX002`, `AX003`, `AX005`, and `AX006` explicitly focus on evaluating or enhancing the GPT-4 family of models.
* **Prompting & Framework Engineering**:
  * `AX001` (WeiZhe Xu et al.) proposes sequential prompt elimination to optimize branch coverage.
  * `AX002` (Yibo Wang et al.) assesses the effectiveness of iterative prompt feedback loops for self-repair.
  * `AX006` (Guancheng Wang et al.) injects call-chain contexts into the prompt to resolve target class dependencies.
  * `CORE001` (KTester) injects project structures and testing guidelines into LLM prompts.

### 3. Comparison (C)
* **Human Manual Baselines**:
  * `AX003` compares GPT-4 tests against human developer reference tests via the TestEval framework.
  * `AX009` benchmarks LLMs against the original open-source developer-written test suites.
  * *Our Research Gap*: No paper directly compares GPT-4 against **student-written manual unit tests** in academic/capstone contexts, which forms our unique comparison baseline.
* **Automated Baselines**:
  * `AX005` and `AX007` use EvoSuite (Search-Based Software Testing) as a traditional baseline.
  * `AX006` (vs. PANTA) and `CORE001` (vs. plain LLMs) use advanced state-of-the-art baselines.

### 4. Outcome (O)
* **Branch Coverage ≥ 80%**: Measured using standard structural testing tools (JaCoCo for Java, coverage.py for Python).
  * Evaluated by 7 papers (`AX001`, `AX003`, `AX005`, `AX006`, `AX007`, `CORE001`, `AX009`).
  * Evidence (`AX003`, `AX005`) highlights that while LLMs achieve high coverage on simple code, coverage degrades significantly on complex real-world projects.
* **Mutation Score ≥ 60%**: Measured using mutation frameworks (PITest for Java, MutPy/mutmut for Python) to evaluate test suite quality.
  * Measured explicitly by `AX003` and `AX007`.
  * Evidence (`AX003`) demonstrates that GPT-4's mutation scores on un-leaked real-world functions drop to ~41%, showing that structural coverage alone does not guarantee high fault-detection quality.
* **Dual-Metric Requirement**: The target outcome requires achieving **both** high coverage (≥80%) and high mutation score (≥60%) simultaneously, addressing the gap identified in literature where LLMs generate high-coverage but structurally weak tests.
