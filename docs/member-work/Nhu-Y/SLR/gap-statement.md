# Gap Statement - LLM-based Unit Test Generation with Coverage and Mutation Testing

Evidence table: N = 11 papers from ACM Digital Library mini-SLR.

## Các khoảng trống phát hiện

### GAP-T - Technology Gap

Most studies focus on popular commercial or general-purpose LLMs such as GPT, ChatGPT, Codex, or other large language models. However, fewer studies provide a clear comparison between different prompting strategies, model versions, and test generation pipelines under the same experimental setting.

**Bằng chứng:** Các paper như ACM001, ACM002, ACM004 và ACM007 đều đánh giá LLM trong unit test generation, nhưng cách thiết kế prompt, benchmark và điều kiện đánh giá chưa hoàn toàn thống nhất.

### GAP-M - Metric Gap

Many papers use code coverage or branch coverage to evaluate generated tests. However, mutation score and mutation testing are less consistently used, even though they can better measure whether generated tests can detect real faults.

**Bằng chứng:** ACM006 and ACM007 are strongly related to mutation information or mutation score, while several other papers mainly focus on coverage-based evaluation.

### GAP-D - Dataset Gap

The datasets used across studies are not fully standardized. Some papers use small programming tasks, some use real-world functions, and others use tool-specific benchmarks. This makes it difficult to compare results across papers.

**Bằng chứng:** ACM007 focuses on real-world functions, while ACM009 presents a tool-based setting and ACM005 focuses on coverage feedback. The dataset types are different across studies.

### GAP-C - Comparison Gap

Many studies compare LLM-generated tests with other tools or with different LLM settings. However, fewer studies directly compare LLM-generated unit tests with human-written unit tests, especially tests written by students or beginner programmers.

**Bằng chứng:** The selected ACM papers focus mainly on LLM performance, coverage, mutation score, or tool improvement, but direct comparison with student-written tests is still limited.

## Phát biểu GAP tổng hợp

Although LLMs show strong potential for automated unit test generation, existing studies still lack a consistent benchmark that evaluates generated tests using both branch coverage and mutation score. In addition, there is still limited direct comparison between LLM-generated unit tests and human-written tests, especially in educational programming contexts.

## Proposed Research Direction

This study can address the gap by comparing unit tests generated by GPT/LLM models with human-written student tests on the same programming tasks. The comparison should use both branch coverage and mutation score to evaluate not only whether the tests execute code paths, but also whether they can detect faults effectively.
