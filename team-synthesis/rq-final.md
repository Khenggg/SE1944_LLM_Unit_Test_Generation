# Research Question Final

> [!NOTE]
> Please note that this document represents the "technical final RQ" up until this point in the research synthesis process. This should not be considered the exact, absolute final RQ, as there is one more major phase incoming (RBL-3) that would necessitate further refinements to these questions.

## Topic

LLM for Unit Test Case Generation.

## Main Research Question

For Java/Python functions with medium cyclomatic complexity (CC = 5–15), can GPT-4o-generated unit tests (using model version gpt-4o-2024-05-13 under zero-shot prompting) achieve a branch coverage of >=30.22%, a mutation score floor of >=4.0%, and a mutation score target of >=40.21%, and how do their performance metrics compare with student-written unit tests on the exact same functions?

## Sub-questions

| RQ | Question | Main Metric |
| --- | --- | --- |
| RQ1 | Do GPT-4o-generated unit tests achieve a branch coverage of >=30.22% on the selected medium-complexity Java and Python functions? | Branch coverage |
| RQ2 | Do GPT-4o-generated unit tests achieve a mutation score of >=4.0% (empirical floor) and >=40.21% (target) on the exact same selected functions? | Mutation score |
| RQ3 | Is there a statistically significant difference in branch coverage and mutation score when comparing GPT-4o-generated unit tests to student-written unit tests evaluated on the same functions? | Paired metric difference |
| RQ4 | Do GPT-4o-generated unit tests achieve both the branch coverage threshold (>=30.22%) and the mutation score floor threshold (>=4.0%) simultaneously for a statistically significant majority (over 50%) of the functions? | Simultaneous success rate |
| RQ5 | What are the predominant failure patterns and technical limitations (e.g., compilation or execution issues) that prevent GPT-4o-generated unit tests from reaching these thresholds? | Compilation/pass status; qualitative failure analysis |

## PICO Framework

| Component | Description |
| --- | --- |
| **P - Population** | Java and Python functions strictly filtered for medium cyclomatic complexity ($5 \le CC \le 15$), utilizing a dataset scale of 10 to 20 representative functions. |
| **I - Intervention** | Automated unit test suites generated by GPT-4o (specifically version `gpt-4o-2024-05-13`) utilizing a standardized, fixed zero-shot prompt protocol with `temperature = 0` to ensure reproducibility. |
| **C - Comparison** | Student-written unit test suites designed for the exact same target functions (academic/student baseline). |
| **O - Outcome** | Achievement of branch coverage >=30.22% (GS017 floor), mutation score floor >=4.0% (GS005 floor), and mutation score target >=40.21% (GS017 target); simultaneous success rate >50% (Exact Binomial Test); and paired statistical comparison. |

## Metrics & Thresholds

| Metric | Threshold / Usage | Recommended Tooling |
| --- | --- | --- |
| Branch coverage | Primary threshold: >=30.22% (empirical floor from GS017) | JaCoCo for Java; coverage.py/pytest-cov for Python |
| Mutation score (Floor) | Floor threshold: >=4.0% (empirical floor from GS005) | PIT/PiTest for Java; mutmut/MutPy for Python |
| Mutation score (Target) | Target threshold: >=40.21% (empirical target from GS017) | PIT/PiTest for Java; mutmut/MutPy for Python |
| Simultaneous success rate | Dual success (BC >= 30.22% and MS >= 4.0%) achieved for >50% of the functions | Exact Binomial Test |
| Compile/pass status | Generated tests must successfully compile and execute before coverage and mutation metrics can be considered valid | Maven/Gradle for Java; pytest test runner for Python |
| Paired difference | Direct comparative analysis between GPT-generated tests and student-written tests evaluated on the exact same functions | Paired Wilcoxon signed-rank test |

## Scope & Threshold Rationale

The consolidated evidence from the Systematic Literature Review demonstrates that the highest quality, most reliable results are predominantly achieved by state-of-the-art models like GPT-4o. Therefore, the final research questions explicitly target GPT-4o-generated unit tests (specifically version `gpt-4o-2024-05-13` with temperature = 0 to guarantee deterministic, reproducible outputs).

**Threshold Justification:**
1. **Branch Coverage (>=30.22%):** Derived from Paper [GS017] / [010] (Huang et al., 2026), representing the average branch coverage achieved by major LLMs on real-world functions under the data-leakage-free ULT (UnLeakedTestBench) benchmark.
2. **Mutation Score Floor (>=4.0%):** Derived from Paper [GS005] / [026] (Wang et al., 2026 - MUTGEN), which represents the empirical floor in the evidence table and serves as a critical warning against evaluating test suites solely on code coverage (where 100% coverage was observed to pair with only a 4% mutation score).
3. **Mutation Score Target (>=40.21%):** Derived from Paper [GS017] / [010] (Huang et al., 2026), representing the average mutation score achieved by SOTA models on the ULT benchmark.

These values provide empirically grounded, scientifically sound thresholds for evaluating LLM test generation efficacy in a realistic scenario.
