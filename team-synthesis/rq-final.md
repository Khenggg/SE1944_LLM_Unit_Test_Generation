# Research Question Final

> [!NOTE]
> Please note that this document represents the "technical final RQ" up until this point in the research synthesis process. This should not be considered the exact, absolute final RQ, as there is one more major phase incoming (RBL-3) that would necessitate further refinements to these questions.

## Topic

LLM for Unit Test Case Generation.

## Main Research Question

For Java/Python functions with medium cyclomatic complexity, can GPT-4/GPT-4o-generated unit tests achieve a branch coverage of >=30.22% and a mutation score of >=35.3%, and how do their performance metrics compare with student-written unit tests on the exact same functions?

## Sub-questions

| RQ | Question | Main Metric |
| --- | --- | --- |
| RQ1 | Do GPT-4/GPT-4o-generated unit tests achieve a branch coverage of >=30.22% on the selected medium-complexity Java and Python functions? | Branch coverage |
| RQ2 | Do GPT-4/GPT-4o-generated unit tests achieve a mutation score of >=35.3% on the exact same selected functions? | Mutation score |
| RQ3 | Is there a statistically significant difference in branch coverage and mutation score when comparing GPT-4/GPT-4o-generated unit tests to student-written unit tests evaluated on the same functions? | Paired metric difference |
| RQ4 | What are the predominant failure patterns and technical limitations that prevent GPT-4/GPT-4o-generated unit tests from reaching the target thresholds? | Compilation/pass status; qualitative failure analysis |

## PICO Framework

| Component | Description |
| --- | --- |
| **P - Population** | Java and Python functions or methods strictly filtered for medium cyclomatic complexity (ideally CC = 5-15). |
| **I - Intervention** | Automated unit test suites generated by GPT-4/GPT-4o utilizing a standardized, fixed prompt protocol without human intervention. |
| **C - Comparison** | Student-written unit test suites designed for the exact same target functions. |
| **O - Outcome** | Achievement of branch coverage >=30.22% and mutation score >=35.3%; successful compilation and execution status; and a paired statistical comparison against the student-written baseline. |

## Metrics & Thresholds

| Metric | Threshold / Usage | Recommended Tooling |
| --- | --- | --- |
| Branch coverage | Primary threshold: >=30.22% | JaCoCo for Java; coverage.py/pytest-cov for Python |
| Mutation score | Primary threshold: >=35.3% | PIT/PiTest for Java; mutmut/cosmic-ray/MutPy for Python |
| Compile/pass status | Generated tests must successfully compile and execute before coverage and mutation metrics can be considered valid | Maven/Gradle for Java; pytest test runner for Python |
| Paired difference | Direct comparative analysis between GPT-generated tests and student-written tests evaluated on the exact same functions | Paired statistical tests (e.g., Wilcoxon signed-rank test) |

## Scope & Threshold Rationale

The consolidated evidence from the Systematic Literature Review demonstrates that the highest quality, most reliable results are predominantly achieved by state-of-the-art models like GPT-4 and GPT-4o, often enhanced by iterative feedback loops. Therefore, the final research questions explicitly target GPT-4/GPT-4o-generated unit tests rather than a generalized "LLM" terminology.

**Threshold Justification:** The baseline thresholds of 30.22% for branch coverage and 35.3% for mutation score are derived directly from the consolidated SLR evidence. Specifically, the 30.22% branch coverage threshold represents the average branch coverage achieved by major LLMs on real-world Python functions under the ULT (UnLeakedTestBench) benchmark in Paper 010 (Huang'26). The 35.3% mutation score threshold represents the median mutation score of LLM-generated tests on industrial Python repositories in Paper 033 (Tabassum'26). These values provide empirically grounded, scientifically sound floor thresholds for evaluating LLM test generation efficacy in a realistic scenario.
