# Research Question Final

## Topic

LLM for Unit Test Case Generation.

## Main Research Question

For Java/Python functions with medium cyclomatic complexity, can GPT-4/GPT-4o-generated unit tests achieve branch coverage >=80% and mutation score >=60%, and how do they compare with student-written unit tests on the same functions?

## Sub-questions

| RQ | Question | Main metric |
| --- | --- | --- |
| RQ1 | Do GPT-4/GPT-4o-generated unit tests achieve branch coverage >=80% on the selected medium-complexity Java/Python functions? | Branch coverage |
| RQ2 | Do GPT-4/GPT-4o-generated unit tests achieve mutation score >=60% on the same functions? | Mutation score |
| RQ3 | Are GPT-4/GPT-4o-generated unit tests significantly different from student-written unit tests on branch coverage and mutation score? | Paired metric difference |
| RQ4 | Which failure patterns prevent GPT-4/GPT-4o-generated tests from reaching the thresholds? | Compile/pass status; qualitative failure reasons |

## PICO

| Thành phần | Nội dung |
| --- | --- |
| P - Population | Java/Python functions or methods with medium cyclomatic complexity, ideally CC = 5-15. |
| I - Intervention | Unit tests generated by GPT-4/GPT-4o using a fixed prompt protocol. |
| C - Comparison | Student-written unit tests for the same functions. |
| O - Outcome | Branch coverage >=80%, mutation score >=60%, compile/pass status, and paired comparison against student-written tests. |

## Metric / Threshold

| Metric | Threshold / use | Tool suggestion |
| --- | --- | --- |
| Branch coverage | Primary threshold: >=80% | JaCoCo for Java; coverage.py/pytest-cov for Python |
| Mutation score | Primary threshold: >=60% | PIT/PiTest for Java; mutmut/cosmic-ray/MutPy for Python |
| Compile/pass status | Generated tests must compile and run before coverage/mutation is trusted | Maven/Gradle/pytest test runner |
| Paired difference | Compare GPT-generated tests and student-written tests on the same functions | Paired statistical test |

## Scope Decision

Evidence merged cho thấy kết quả tốt nhất thường đến từ GPT-4/GPT-4o hoặc các LLM pipeline có feedback loop. Vì vậy RQ final dùng `GPT-4/GPT-4o-generated unit tests` thay vì chỉ nói chung chung `LLM-generated tests`. Nếu nhóm không có quyền dùng GPT-4o khi chạy thực nghiệm, cần thay tên intervention bằng model thực tế trước khi nộp báo cáo.
